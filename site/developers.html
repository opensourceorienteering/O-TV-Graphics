Developers

Split Control's graphics are plain web files: HTML, CSS and JavaScript modules following the EBU OGraf standard. A look is a family of graphics sharing one style. This page shows how to make your own and test it.

Preview tool: try every look with a simulated race, or load your own look's zip, right in your browser.

Open the preview

Preview tool

The preview runs the real graphics, the same files the app uses, without installing anything:

  • Look and graphic: every look on this site, plus any look you load as a zip. Your zip stays in your browser; nothing is uploaded.
  • Show, Update, pages, Hide as on the Live desk, with the same keys: Space, U, ← →, H.
  • Race simulator: twelve runners start at a two-minute interval and pass four radio controls and the finish, with one mispunch and one runner who gives up. Run it at 1× to 60×, or jump two minutes ahead. With Live updates on, graphics on air change as results come in, as they do in the app.
  • Data: timing point, runner, broadcast language, clubs or flags, the three theme colours, and any extra fields as JSON (titles, texts, names).
  • Backgrounds: forest, transparent, dark and light, to check contrast.

Load the same zip again after a change: it replaces the earlier copy. Remove loaded looks clears them all.

How a look works

Every look has the same 17 graphics. The markup is shared: it comes from sets/_core/, which ships with the app. A look only decides the style and motion, mostly in one CSS file.

sets/
├── _core/                 shared code (ships with the app, not part of a look)
│   ├── graphic.js         the OGraf Web Component: lifecycle, pages, clocks, scaling
│   ├── views.js           data → markup for every graphic
│   └── base.css           placement and structure shared by all looks
└── my-look/               one look
    ├── set.json           name, description, the three theme colours
    ├── set.js             durations, name styles, labels (read by the graphics)
    ├── theme.css          the style and the motion
    ├── fonts/             fonts.css, font files and licence (see Fonts)
    └── my-look-results/   one folder per graphic: manifest + a 4-line graphic.js
        ├── my-look-results.ograf.json
        └── graphic.js

A graphic's graphic.js is only this:

import { createGraphic } from '../../_core/graphic.js';
import set from '../set.js';
export default createGraphic('results', set);

Because graphics import ../../_core/, a look always runs with the shared code of the app it's in. That keeps every look up to date with new features and fixes.

Change an existing look

For new colours, fonts or details on a look you already use, no tools are needed (for a new font, see Fonts):

  1. In Split Control, Graphics library → Export… next to the look, or download it from the Looks page.
  2. Unzip it and edit theme.css (and set.json for the name and colours). Keep the look's id ("id" in set.json).
  3. Zip the look's folder again and load it in the preview to check it.
  4. Import it in the app: it replaces the look with the same id. For a built-in look like Standard, removing your copy brings the original back.

Make a new look

A new look needs its own id, and its graphics need unique ids. The repository has a generator that writes all 17 graphic folders for you.

  1. Get the code: git clone https://github.com/opensourceorienteering/O-TV-Graphics, then npm install (Node.js 22 or newer).
  2. Copy a look that is close to what you want, e.g. templates/sets/standard to templates/sets/my-look, and delete its graphic folders (standard-*).
  3. Edit set.json (id, name, description, colours) and set.js (id, and colorVars: the CSS variables the three theme colours set).
  4. Add the look to SETS in scripts/generate-template-sets.js and run npm run generate:sets.
  5. Style it in theme.css. To see changes, either run the app (npm run dev, then Scan library), or zip the folder and load it in the preview.

Every look in the repository is a working example. standard is a good start; sof follows a full graphic manual. See also templates/sets/README.md.

Styling the graphics

Start theme.css with @import url('../_core/base.css');. The canvas is 1920 × 1080; graphics scale to the output size.

Markup

.gfx.gfx--<kind>The graphic, e.g. .gfx--results. Carries data-state (see Motion).
.panel.panel--<type>One block: --table, --lower, --strap, --side, --title, --clock, --podium, --chart…
.hdr / .ftrHeader and footer: .hdr-title, .hdr-sub, .hdr-logo, .ftr-page…
.rows > .rowTable rows. --i is the row's index, for staggered animation. .row--leader, .row--hl (the runner in focus), .row--status (MP, DNF…).
Cells.c-place, .c-name, .c-id (club, flag), .c-time, .c-bib, .c-start, .c-label, .c-value, .c-change

Variables

Placement is set with variables, so a look rarely needs to move panels itself: --margin-x, --margin-y, --table-top, --table-x, --lower-w, --side-w, --title-x, --podium-x. Chart lines use --line-0 to --line-7.

Theme colours

Operators can change three colours per event (Plan → Theme). colorVars in set.js names the CSS variables they set, and colors in set.json gives the defaults, in the same order. Derive every other shade from those three (color-mix(), relative colours), so a change follows everywhere.

Rules every look follows

  • Keep the centre of the picture clear: lower thirds bottom left, side panels bottom right, the clock top right.
  • Numbers use tabular figures, so running times don't wobble.
  • Names and texts end in an ellipsis instead of overflowing. Check long names and accents (Å, Ä, Ö, Ø).
  • The event logo appears only on the start list, results and race title card, at least 42 px tall.
  • Bundle every font the look uses (see Fonts).

Fonts

A look carries its own fonts. Production computers are often borrowed or freshly installed, so the look must not depend on fonts installed on the computer. If it does, it looks different on every machine, or falls back to Arial on air.

What goes in the look

my-look/
├── set.js                 fonts: points at fonts/fonts.css
├── theme.css              --font: "Libre Franklin", Arial, sans-serif;
└── fonts/
    ├── fonts.css          one @font-face per weight and style
    ├── libre-franklin-latin-600-normal.woff2
    ├── libre-franklin-latin-ext-600-normal.woff2
    └── LICENSE-libre-franklin.txt
  • fonts/fonts.css declares the fonts with @font-face, pointing at files next to it (url(./…woff2)). set.js names it as fonts. The graphics load it into the page for you: @font-face does not work inside a graphic's shadow DOM, so don't declare fonts in theme.css.
  • Font files: use .woff2. Include the latin and latin-ext subsets so names like Ørjan, Hägström, Čech and Łukasz render in the same font.
  • Every weight you use: if theme.css asks for 800 and you only bundle 400, the browser fakes a bold that looks smeared on air. Bundle each weight the look uses (italics only if it uses them).
  • The licence file goes in fonts/. Bundle only fonts you are allowed to share: SIL Open Font License (OFL) and Apache fonts are fine. Commercial fonts usually are not.

Font stacks

Put the bundled font first, then a common system font and a generic family:

.gfx {
  --font: "Libre Franklin", Arial, sans-serif;
}

Don't put an installed font in front of the bundled one, even a brand font. Computers that have it (Franklin Gothic comes with Microsoft Office, for example) would show a different look from those that don't.

Brand fonts you can't share

Many federation and broadcaster fonts are commercial (ITC Franklin Gothic for the IOF, GT Planar for ČO). Bundle a free stand-in that is close in shape and width, and say so in set.json; the Looks page shows it:

"fonts": "Libre Franklin (OFL), bundled; it stands in for ITC Franklin Gothic"

A broadcaster who owns the brand font can make their own copy of the look with the font files in fonts/, keeping the copy to themselves.

Where to get the files

Fontsource has most open fonts already split by weight and subset, with ready-made @font-face rules: download the font, copy the .woff2 files you need into fonts/, and change the url()s to ./file.woff2. The looks in the repository were made this way.

Check it

  • Load the zip in the preview. In the browser's developer tools, the Network tab should show your .woff2 files loading, with no 404s.
  • Check that numbers have tabular figures (running times shouldn't wobble) and that accented names use the same font.
  • In the repository, npm test fails if a look uses a font it doesn't bundle, points to a missing file, or loads files from another look.

Motion

The graphic sets data-state on .gfx; animate with CSS keyframes for each state. The durations in set.js say how long each state lasts.

inEntering (durations.in)
onOn air. Live changes flash with .is-changed; rows slide to their new place.
step-out / stepChanging page (durations.stepOut, durations.step)
leaveLeaving (durations.out)
outHidden

Animate only transform and opacity: they stay smooth in NDI capture. Don't follow the computer's Reduce Motion setting: broadcast output must look the same on every machine.

The data graphics get

The app sends the same data to every look. The main fields:

results[]Runners at the shown timing point: name, club, country, bib, position, time, diff, statusCode (0 OK, 1 DNS, 2 DNF, 3 MP, 4 DSQ), startTimeMs, splitTimes[]
className, controlCode, splitControls[]Class, timing point (S, a control code or F) and the class's radio controls
runnerName, runnerClub, runnerBibThe runner in focus (lower thirds, identity, runner focus)
title, series, place, date, text, name…Fields the operator fills in
presentationlanguage, identity (club, flag, both), themeColors, logoUrl
clockOffsetMsServer time minus this computer's time, for running clocks

The preview's More data (JSON) box shows and edits these fields.

Test before race day

  • All 17 graphics, on air and while changing page.
  • Long names and clubs, accents, and 10+ runners (the results table pages).
  • Clubs, flags, and both; English and Swedish labels.
  • Live updates: run the simulator at 20× with a results table on air.
  • Transparent and light backgrounds.
  • In the app: Plan → Theme preview, then the web output in OBS or vMix.
  • To rehearse with real timing data, replay a finished race.

Share a look

  • As a zip: zip the look's folder (my-look/ at the top of the zip), including fonts/. Anyone can import it in Graphics library → Import look….
  • On this site: open a pull request adding your look to templates/sets/. Every look there appears on the Looks page and in the preview.

Other OGraf graphics

Graphics that aren't part of a look also work: any EBU OGraf v1 package (a folder with <name>.ograf.json and its module) can be imported as a zip and appears in Split Control's Graphics library. Split Control also speaks the OGraf Server API at http://<computer>:5657/ograf/v1.
