# Milestone 3b-1: Field Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** A graphic made elsewhere (for example in OGraf Studio) can show our data under its own field names. `v_olgrafik_fieldMap` in its manifest says which of our data goes into which of its fields.

**Spec:** `docs/superpowers/specs/2026-11-20-graphics-library-and-import-helper-design.md`, section 7. The import helper (3b-2) writes this map; this part reads it.

## Global Constraints

- **Our data keys** (`OUR_KEYS` in `src/shared/fieldMap.ts`):
  - runner: `runnerName`, `runnerClub`, `runnerBib`;
  - class and timing point: `className`, `controlName`;
  - event: `title`, `series`, `place`, `date`, plus `event.name`, `event.location`, `event.date`, `event.series`, `event.organiser`;
  - course: `length`, `climb`, `controls`, `winningTime`, `startInterval`, `legs`;
  - weather: `condition`, `temperature`, `wind`, `humidity`.
  - Dotted keys read nested objects.
- **Our list:** `results`. Its row keys (`ROW_KEYS`) are `name`, `club`, `country`, `bib`, `position`, `time`, `diff`, `status`, `startTime`, plus the derived `timeSeconds` and `diffSeconds`. These are numbers parsed from `time` ("1:02:03", "15:52") and `diff` ("+1:23"); unparseable gives `null`.
- **Map shape:**
  - `{ graphicKey: ourKey }` for a single value;
  - `{ graphicKey: { from: 'results', items: { rowKey: ourRowKey } } }` for a list.
- **Applying:**
  - mapped keys are set from our data;
  - every other key passes through unchanged (typed fields keep working);
  - our original keys stay too, since graphics ignore what they don't know;
  - a mapped key whose value is missing in our data is left as it was, so a typed or default value survives.
- **Where it applies:** `PlaybackEngine.decorateData`, which every app path goes through (Show, Update, live updates, refresh), and the library preview. It never applies to the OGraf Server API (`api*` methods).
- **Validation:** `resolveDeskDeclaration` adds desk warnings for:
  - a map that isn't an object;
  - a graphic key that is not in the schema;
  - an unknown key of ours;
  - a list mapped from anything other than `results`, or onto a schema field that is not an array;
  - an unknown row key.

## Tasks

### Task 1: `src/shared/fieldMap.ts`
- **Functions:** `applyFieldMap(map, data)`, `fieldMapWarnings(map, schema)`, `parseClock(text)`, and the `OUR_KEYS` / `ROW_KEYS` catalogues.
- **Tests:**
  - a single value;
  - a dotted key;
  - a list with derived seconds;
  - unknown keys pass through;
  - a missing value keeps the typed one;
  - warnings for each case listed above;
  - `parseClock` on "15:52", "1:02:03", "+1:23", "-", "" and numbers.

### Task 2: Validate in `resolveDeskDeclaration`
- Add the warnings from `fieldMapWarnings` (prefixed `v_olgrafik_fieldMap:`), so a bad map shows under Needs attention.
- **Test:** in `deskDeclaration.test.ts`.

### Task 3: Apply in the engine and the library preview
- `decorateData` takes the graphic's manifest and applies its map last.
- Pass the manifest at all four call sites.
- The library preview (`sampleGraphicData`) applies it too.
- **Tests:**
  - PlaybackEngine: a graphic with a map receives mapped data on Show, and `apiLoad` data is untouched;
  - sampleData: the preview of a mapped graphic gets mapped data.
